What you're deploying

A phone acts as an edge camera node. It captures a number plate and posts the frame to a local server, which reads the plate with Claude Vision (falling back to local Tesseract OCR), matches it against a vehicle registry, applies policy, and pushes the result to a control-room dashboard over WebSockets — firing an audible and visual alarm when a wanted vehicle appears.

Two independent stacks

The repository contains two systems that run side by side:

StackPortsWhat it is
surveillance 8000 / 8443 The AI surveillance prototype — live dashboard, detection API, WebSocket hub, browser scanner. Pairs with the Android app.
console 4000 / 4443 The ANPR traffic admin console — watchlists, compliance notices, green corridor, toll, role-based logins.

The HTTPS port on each is required only for browser camera access from a phone — browsers block getUserMedia on insecure origins.

The server uses Node's built-in node:sqlite module, which means no native compilation — no Visual Studio Build Tools, no Python, no database server to install. Older Node versions do not have this module.

Data persistence

Each stack stores its SQLite database in a named Docker volume. Restarts and rebuilds never lose data — seeding runs only when the database is missing or empty. To reset to fresh demo data, use docker compose down -v then up -d.

03 Enable Claude Vision

The system runs out of the box on local Tesseract OCR. This is the weakest link — Tesseract misreads embossed, angled, and hand-lettered plates often. Claude Vision is substantially more accurate and is strongly recommended for real testing.

Create a .env file next to docker-compose.yml:

.env — repo root
# Enables Claude Vision as the primary OCR engine.
ANTHROPIC_API_KEY=sk-ant-...

# Your PC's LAN IP — needed so phone HTTPS certificates cover it.
HOST_IP=192.168.1.5

Apply it, then confirm which engine is active:

repo root
docker compose up -d --force-recreate

curl http://localhost:8000/api/health

The response reports "vision": "claude-vision + tesseract-fallback" when the key is picked up, or "tesseract-only" when it isn't.

How the pipeline degrades

  1. Claude Vision runs first, returning strict JSON via structured outputs — {"plate_number": "KL07B1234", "confidence": 0.95}.
  2. If it fails, errors, or returns confidence below 0.4, the request falls through to Tesseract (three preprocessing variants × two segmentation modes).
  3. The read is normalised by plate position — correcting O↔0, I↔1, S↔5, Z↔2 according to whether each slot should hold a letter or a digit.
  4. If the plate isn't in the registry, a fuzzy match (edit distance ≤ 2) offers the closest registered plates as one-tap suggestions.
No key required

Everything works without an API key — the system simply uses Tesseract for every read. Add the key later and restart; no rebuild is needed.

04 Phone connectivity

Getting the phone to reach the server is the step most likely to fail. There are three ways, in order of convenience.

Option A — Wi-Fi (best for field testing)

Phone and PC on the same network. Find your LAN IP:

powershell
ipconfig | Select-String IPv4
Windows Firewall will block this by default

Windows blocks inbound connections on networks classified Public — which includes Hyper-V virtual switches, a common surprise. Connections simply time out with no error. Run once in an Administrator PowerShell:

powershell — as administrator
New-NetFirewallRule -DisplayName "ANPR" -Direction Inbound `
  -Protocol TCP -LocalPort 8000,8443 -Action Allow -Profile Any

Verify from the phone's browser: http://<your-ip>:8000/api/health.

Option B — USB tunnel (no firewall changes)

With the phone plugged in and USB debugging on, forward the ports over the cable. The phone then reaches the server at localhost, bypassing the network entirely.

any shell
adb reverse tcp:8000 tcp:8000
adb reverse tcp:8443 tcp:8443

# confirm the phone can reach it
adb shell curl -s http://localhost:8000/api/health

In the app, set the server address to http://localhost:8000. The tunnel drops when you unplug — re-run the commands to restore it.

Option C — Everything on the PC

Skip the phone entirely: use the browser scanner at http://localhost:8000/scan.html with a webcam, or type plates into the manual-entry field to exercise the full business logic.

05 Browser scanner

The fastest way to scan from a phone — nothing to install. Requires HOST_IP to be set (see step 3) so the certificate covers your address.

  1. Put the phone on the same Wi-Fi as the PC.
  2. Open https://<your-ip>:8443/scan.html — note https.
  3. Accept the certificate warning once (Advanced → Proceed).
  4. Allow camera access, aim at a plate, tap Capture & Scan.
Why the certificate warning appears

Browsers only allow camera access on secure origins, so the server generates a self-signed certificate on first run. The warning is expected and appears once per device.

The scanner crops to the on-screen guide box before uploading, has a manual plate field, an auto-scan toggle, and a front/back camera flip.

06 Build the Android app

This produces a release APK with the JavaScript bundled in, so the app runs standalone — no Metro dev server tethered, which matters when walking around with model cars.

Install dependencies

surveillance/mobile
cd surveillance/mobile
npm install

# verify the project is consistent — expect 18/18 checks passed
npx expo-doctor
Native modules already declared

The app depends on expo-camera, expo-file-system, expo-image-manipulator, expo-asset, expo-system-ui and expo-build-properties. All are in package.json — npm install is enough. They are each load-bearing: file-system provides the storage interface the camera writes photos through, and image-manipulator does the crop that makes OCR usable.

Generate the native project

surveillance/mobile
npx expo prebuild --platform android

Point Gradle at the Android SDK

powershell — surveillance/mobile/android
cd android
Set-Content -Path local.properties -Encoding ascii `
  -Value 'sdk.dir=C:/Users/YOUR_USERNAME/AppData/Local/Android/Sdk'
Use forward slashes

local.properties is a Java properties file, where a backslash starts an escape sequence — C:\Users\... fails to parse and the build dies with “The filename, directory name, or volume label syntax is incorrect.” Forward slashes work on Windows and avoid the problem entirely.

Build the APK

powershell — surveillance/mobile/android
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME

.\gradlew.bat assembleRelease --no-daemon

First build takes roughly 8–10 minutes (it downloads Gradle and compiles all native modules); later builds are 2–3 minutes. The output lands at:

path
surveillance/mobile/android/app/build/outputs/apk/release/app-release.apk
Run Gradle from PowerShell, not Git Bash

Git Bash rewrites Windows paths (MSYS path conversion), which breaks Expo's autolinking scripts mid-build. PowerShell or CMD avoids this.

Install on the device

Enable Developer options → USB debugging, plug in, and confirm it's visible:

any shell
adb devices

adb install -r app/build/outputs/apk/release/app-release.apk
Xiaomi / Redmi / POCO devices

MIUI blocks ADB installs by default and returns INSTALL_FAILED_USER_RESTRICTED. Enable Developer options → Install via USB (this requires being signed into a Mi account). Alternatively, push the APK and tap it in the Files app:

any shell
adb push app-release.apk /sdcard/Download/anpr-edge-camera.apk

First launch

  1. Open ANPR Edge Camera.
  2. Enter the server address — http://192.168.1.5:8000 for Wi-Fi, or http://localhost:8000 when using the USB tunnel.
  3. Set a camera node ID (identifies this device in logs and alerts).
  4. Tap Connect, then grant camera permission.

Both settings persist, so subsequent launches skip straight to the scanner.

07 Test the system

The seed data includes five deliberately simple plates — one per business-logic branch — chosen to be easy to hand-letter onto scale-model cars.

PlateStatusExpected result
KL07B1234 NORMAL Green card — owner Rajesh Menon, 2 unpaid fines totalling ₹2,000
KA01AB1111 SURVEILLANCE Amber card, sighting appended to the movement trail
MH12CD2222 WANTED Red banner, alarm tone, phone vibration
TN09XY7777 WANTED Second wanted vehicle, for multi-alert testing
DL03EF4444 SURVEILLANCE Amber, tracked across camera nodes

Test without a camera first

Confirm the business logic end to end before involving optics:

any shell
curl -X POST http://localhost:8000/api/detect \
  -H "Content-Type: application/json" \
  -d '{"plate_number":"MH12CD2222","camera_node_id":"NODE-01"}'

With the dashboard open you should see the red banner fire instantly. Every scanner also has a manual plate field that does the same thing.

Test the camera

Open http://localhost:8000/plate.html on the PC. It renders large, high-contrast plates with buttons to switch between all five. Aim the phone's guide box so the plate fills the box.

Print the plate if you can

Photographing a monitor produces moiré interference — the concentric ripple pattern that appears when a camera shoots a pixel grid — which measurably degrades OCR. Paper is markedly more reliable. Press Ctrl+P on the plate page.

Plate format is enforced

Plates must match the Indian structure: two state letters, one or two RTO digits, one to three series letters, four digits. Something like KA 1352 has no series letters, is structurally invalid, and will be rejected even if OCR reads it perfectly. Use the seeded plates above.

What to check on the dashboard

  • Live Dashboard — detections stream into the feed as they happen.
  • Surveillance Tracking — flagged vehicles plotted as a path across camera nodes.
  • Vehicle Directory — search the registry, change any vehicle's status, add plates.
  • Alerts — every critical alert, with acknowledge.
  • Audit & Export — full audit trail plus CSV/JSON export of all tables.
Audio

Browsers block sound until the page has been interacted with. Click anywhere in the dashboard once after loading, and the alarm tone will play on subsequent alerts.

08 Run without Docker

Useful for development, with hot reload on both server and dashboard.

terminal 1 — surveillance/server
cd surveillance/server
npm install
npm run seed      # creates and fills the database
npm run dev       # starts on :8000 and :8443
terminal 2 — surveillance/admin
cd surveillance/admin
npm install
npm run dev       # dashboard on :5180, proxies API to :8000

The server prints its LAN addresses on startup — use those in the mobile app. Building the dashboard (npm run build in admin/) makes the server host it directly on port 8000, so a single port serves everything.

The original admin console runs the same way on ports 4000/4443:

repo root
cd server && npm install && npm run seed && npm run dev
cd client && npm install && npm run dev

Database schema

SQLite via Node's built-in node:sqlite. The file lives at surveillance/server/data/surveillance.db, or inside a Docker volume when containerised.

TableKey columns
vehiclesplate_number, owner_name, vehicle_model, registration_date, status, status_reason
finesplate_number, violation_type, amount, date_issued, paid_status
movement_logsplate_number, camera_node_id, detected_at, snapshot_url, confidence
alertsplate_number, movement_log_id, camera_node_id, severity, acknowledged
audit_logsevent_type, description, timestamp
camera_nodesid, label, location, lat, lng, last_seen_at

status is constrained to NORMAL, SURVEILLANCE or WANTED_CRIMINAL — these three values drive the entire alerting pipeline.

Troubleshooting

Every issue below was hit during the build and verified fixed.

Server and dashboard

SymptomCause & fix
Empty reply, or dashboard shows “Reconnecting…” Docker Desktop stopped. Restart it, then docker compose up -d.
EADDRINUSE on start An old server still holds the port. Find and kill it: netstat -ano | findstr :8000 then taskkill /PID <pid> /F.
Page reloads in a loop A stale built bundle. Rebuild with docker compose up -d --build and hard-refresh (Ctrl+Shift+R).
No alarm sound Browsers block audio before user interaction. Click once in the page.

Phone connectivity

SymptomCause & fix
Connection times out from the phone Windows Firewall blocking inbound on a Public network — including Hyper-V switches. Add the firewall rule in step 4, or use the USB tunnel.
Browser scanner shows no camera Page opened over http://. Camera needs a secure origin — use https://<ip>:8443/scan.html.
Certificate doesn't cover the address HOST_IP not set. Containers can't detect the host LAN IP themselves — set it in .env and recreate.
Ping to the PC fails Normal — Windows blocks ICMP by default. It does not indicate TCP is blocked.

Android build and install

SymptomCause & fix
“The filename, directory name, or volume label syntax is incorrect” Backslashes in local.properties. Use forward slashes.
The required package `expo-asset` cannot be found Missing peer dependency. npx expo install expo-asset.
INSTALL_FAILED_USER_RESTRICTED MIUI blocking ADB installs. Enable Install via USB, or push the APK and tap it in Files.
Autolinking fails mid-build Gradle run from Git Bash. Use PowerShell or CMD.
adb shell input permission denied MIUI blocks event injection. Requires USB debugging (Security settings); tap manually instead.

Detection accuracy

SymptomCause & fix
module 'expo.modules.interfaces.filesystem.AppDirectories' not found Missing expo-file-system, which the camera writes photos through. Install and rebuild.
Reads unrelated text from the scene The frame includes background text. Fill the guide box with the plate — the app crops to it before upload.
Plate read but “not in registry” Either a genuine OCR slip — tap the suggested plate — or an invalid plate format that can never match.
Consistently poor reads Tesseract's inherent limit. Set ANTHROPIC_API_KEY to enable Claude Vision; print plates instead of photographing screens.
